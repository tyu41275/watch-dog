# Security policy

Watch Dog has a deployed, deadline-bounded challenge candidate. It is not represented as a general-purpose production security control or a safety guarantee.

## Reporting a vulnerability

Do not disclose a suspected vulnerability, live malicious URL, credential, personal data, or other sensitive evidence in a public issue, discussion, pull request, or corpus contribution.

Use this repository's **Security** tab to submit a private vulnerability report. Include only the minimum reproduction details needed, redact secrets and personal data, and use inert examples where possible.

If private reporting is unavailable, contact the repository owner through their GitHub profile without sending exploit details publicly, and ask for a private reporting channel.

## Scope and response

Reports about the public application, repository configuration, unsafe handling guidance, or accidental sensitive-data exposure are welcome. Receipt will be acknowledged when practical; remediation and disclosure timing will depend on severity and reproducibility. During a recorded judging freeze, critical security fixes take priority and must be disclosed in the submission/release record.

## Safe handling

- Never visit a submitted suspicious URL on a personal or production device.
- Never commit secrets, authentication material, raw personal data, or active malware.
- Do not test against systems you do not own or lack permission to assess.
- Prefer synthetic, redacted, defanged, or otherwise inert indicators in documentation and reports.
